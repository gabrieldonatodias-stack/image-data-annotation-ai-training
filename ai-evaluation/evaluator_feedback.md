# Evaluator Feedback Examples

## Example 1 — Accuracy Issue

**Decision:** Not Preferred

**Feedback:** The response addresses the user's question, but one factual claim is unsupported. The model should verify or qualify that claim before presenting it as fact.

## Example 2 — Instruction Following

**Decision:** Not Preferred

**Feedback:** The response provides relevant information but does not fully follow the requested format. The answer should prioritize the explicit output requirements.

## Example 3 — Strong Response

**Decision:** Preferred

**Feedback:** The response is accurate, relevant and clearly structured. It follows the user's constraints and provides sufficient detail to answer the request.

## Example 4 — Completeness

**Decision:** Not Preferred

**Feedback:** The response correctly addresses part of the request but leaves an important component unanswered. The missing component should be addressed directly.

## Evaluator Principle

The evaluator should judge the model response against the prompt and rubric, not against personal preference.
